# PT++ implementation audit of the RTXDI 3.1 reference

Reference source inspection checked 2026-10-28. B0 preserves unchanged RTXPT1.9 defaults, scenes and dependency pins; runtime3.1 has not been applied to that reference. This table audits the separate SDK/runtime FullSample paths under `work/RTXDI-SDK-reference`, not a build/GPU execution or every renderer. Project labels now follow [canonical B0–B10](VERSION_MAPPING.md): legacy migration7010bb4 is not canonical B1; app-owned PT integration is the B6/B7 foundation; the GI-off limited pilot is a B7 ablation, not B9; full remaining PT++ is B10 work with B8 sharing as a dependency. Those local stages do not alter this reference-source table's evidence scope. Runtime revision: `NVIDIA-RTX/RTXDI-Library@f12037fa8e97ebc08e9e3edfd2de528ed1772a4b`. FullSample source matches SDK `a6efab966b7c3b272da0461578eb56ac61c7cbff`. Paths below are relative to that SDK root: `PT/` means `Libraries/Rtxdi/Include/Rtxdi/PT/`; `Sample/` means `Samples/FullSample/`.

**Conclusion about reference only:** RTXDI 3.1 incorporates an important subset of PT++ and also CGNS, but it is not a complete transfer of every optimization in PT++ §§3–6. Existing code should be enabled/validated where appropriate. Missing paper mechanisms are separate extension candidates; importing the whole paper again would duplicate working features.

## Separate CGNS confirmation

CGNS is already implemented, although it is a separate HPG 2026 paper rather than one of PT++'s original contributions. `PT/SpatialNeighborSelection.hlsli:48–123` implements selection; `PT/SpatialResampling.hlsli:49–58` consumes its buffer; `ReSTIRPTRenderPasses.cpp:102–105` dispatches the selection prepass and barrier. `Libraries/Rtxdi/Source/ReSTIRPT.cpp:110` defaults `enableSpatialHeuristicMode=0`, so the next task is enable-and-validate, not a new algorithm port.

## Roadmap consequence

Preserve B0 original defaults/pins and compare explicit canonical configurations. The [legacy migration report](B1_RESULTS.md) maps historical DI+GI observations to B2/B5; it is not the new B1 native-DI benchmark. B1/B4 need matched native PT + DI measurements. The table identifies reusable reference code and reference-path gaps: unified direct/indirect reservoirs, all-candidate vector shading, reciprocal pairing and explicit replay scheduling. B10 must implement/validate those mechanisms without counting inherited packing/forced NEE again. B8 GI/PT sharing needs its own partition/MIS. A reciprocal+CGNS construction requires derivation; guided neighbors need not be reciprocal. Verify dual motion separately rather than relabelling PSR/zero-motion fallback. Keep bias controls outside strict reference runs. Source inspection remains distinct from the separately scoped [B7 opaque](B2_RESULTS.md) and [GI-off limited-pilot](B3_RESULTS.md) measurements.

Paper reference: [PT++ author PDF](https://cwyman.org/papers/i3d26_ReSTIRPT++.pdf), §§3–6, pp4–11; baseline comparisons §7/Table1 are against the original 2022 implementation and cannot be reused as a speedup prediction for RTXDI 3.1 or RTXPT 1.9.
