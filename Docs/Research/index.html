Inherited PT++ is not a new B9 gain

Runtime 3.1 already supplies 64-byte PT reservoirs, forced terminal NEE reconnection and optional footprint/history/roulette machinery. Source presence is not execution. The historical GI-off pilot wired footprint and initial-only roulette and measured isolated effects; it did not implement reciprocal pairing, explicit replay compaction, unified primary direct/indirect reservoirs, all-candidate vector shading or dual-motion disocclusion recovery. Duplication reduction needs its actual producer/lifecycle and remains deliberately biased. Record inherited mechanisms rather than counting them again. CGNS is a separate paper and is not reciprocal pairing.

What the corrected control changes

The earlier0.806ms migrated native control had DI off. It was not a native PT+DI comparator. The new B4 control has DI on and costs1.289ms in this separately identified registered-environment fixture; B7 costs1.539ms. B8: disjoint DI, GI and ReSTIR PT contribution ownership

Design/source audit only, 2026-10-29 Europe/Zurich. No B8 renderer implementation, build, GPU execution or unbiasedness result is asserted. Use the canonical B0–B10 ledger; this note proposes a transport contract for the requested combined mode.

Main conclusion

DI, GI and PT may run together only after their integrands are disjoint. The current GI path collects the entire suffix after its first eligible non-delta scatter, while current ReSTIR PT also estimates indirect suffixes. Enabling both toggles would overlap. Moreover, “GI owns emission at the first secondary surface” overlaps ordinary DI: camera→primary→emitter already is a primary direct-light path.

Use accepted scattering count, not UI names or raw ray-hit counts:

  • Native owns directly visible emission/environment and explicitly unsupported fallback domains.
  • DI owns one-scattering direct lighting at the primary surface.
  • GI owns a restricted, provably valid two-scattering domain.
  • ReSTIR PT owns three-or-more-scattering paths.

For the first strict GI implementation that reuses unchanged secondary RGB, restrict its secondary endpoint to a verified outgoing-direction-independent Lambertian response. Native traces the remaining two-scattering paths. The current GI reservoir cannot correctly reevaluate glossy secondary outgoing radiance after reconnection, and the default diffuse model is Frostbite, not Lambertian. A later general GI implementation needs extended payload/reevaluation; it must not silently claim exact glossy reuse.

Physical path partition

Let x0 be the camera, x1 the first accepted material surface and x2 the next material surface. Let k be the number of actual BSDF scattering events before reaching emitted light. A path can contain null/alpha-rejected/false-medium interfaces without increasing k. A terminal emissive material can itself scatter on other longer paths; its emitted and scattered terms are distinct contributions.

  • k0: directly visible surface emission or camera environment miss.
  • k1: x0→x1→light. This includes BSDF hits at an emissive x2 and environment after scattering at x1.
  • k2: x0→x1→x2→light. This includes NEE at x2 and BSDF hit/environment after scattering at x2. Emission of x2 itself belongs to k1, not this domain.
  • k≥3: longer paths.

Define deterministic eligibility D(x1) for a valid DI primary, P(x1) for a valid B8 split primary and L(x2) for the restricted GI secondary. For the first strict implementation, P requires first actual surface, opaque nontransmissive material, no medium, unit prefix, one plane/pinhole and no delta lobes at the primary. Do not infer P from the randomly selected BSDF lobe. A mixed-delta primary initially remains native fallback unless a lobe-labelled split is separately derived.

L requires a material/BSDF implementation whose radiance is outgoing-direction-independent within the relevant hemisphere, with compatible normals/sides and no transmission/delta response. Roughness1 or a material named “Diffuse” is not sufficient. BSDFs/BxDFConfig.hlsli defaults DiffuseBrdfFrostbite; a global switch to Lambertian would change the baseline renderer and is not an acceptable hidden test-scene fix. Add an explicit verified material capability or keep L=false for unsupported secondary materials. If the chosen fixture has no qualifying endpoint, report no active GI contribution rather than claiming combined-path coverage.

The proposed characteristic functions are:

chi_DI = D * [k=1]
chi_GI = P * L * [k=2]
chi_PT = P * [k>=3]
chi_N  = [k=0] + (1-D)*[k=1]
         + (1-P)*[k>=2] + P*(1-L)*[k=2]

For every supported physical path, chi_N+chi_DI+chi_GI+chi_PT=1 and each is0or1. For k2, L is evaluated at that path's x2; other domains need not evaluate it. This design keeps PT-long independent of secondary material classification, avoiding a sample-class change under hybrid shifts of a k2 PT path. An alternative PT domain [k>=3] or ([k=2] and !L) would need L reevaluation and corresponding inverse support tests at every shifted k2 prefix; do not implement that shortcut from stored radiance alone.

These masks multiply the physical integrand. NEE and BSDF sampling techniques for one path length still use their internal MIS whose weights sum to one. Do not classify one technique as “DI” and another technique for the same path as “GI”, then count both as complete estimates.

DI contract

At a DI-eligible primary, DI estimates the whole k1 reflected direct term using the pinned DI light/BRDF proposals and its existing actual settings. Native NEE and native continuous BSDF emitter/environment counterparts for that primary must be suppressed consistently. The existing PathTracerNEE.hlsli::HandleNEE DI branch suppresses NEE and sets SkipEmissiveBRDF; current hit/miss code consults that bit. Preserve or explicitly replace both halves under the same D predicate.

Primary directly visible emission, directly visible environment and primary delta/transmission fallback are native domains. Do not allow the k2 GI payload to reintroduce Le(x2) that DI already estimates. For a non-DI primary, native k1 remains active and the other component masks are unchanged. First strict B8 may require DI enabled and reject a missing DI configuration rather than improvise a new direct estimator.

A precise restricted GI initial estimator

At eligible x1, sample a continuous direction omega12 with the full marginal primary BSDF proposal q1(omega12|x1), and trace to accepted x2. If no actual surface is hit, this is a k1 environment event; no GI candidate is created. If L(x2)=false, this draw creates no GI candidate; the native two-scattering fallback independently covers that domain.

For L=true, construct an unbiased estimate Z1(x2) of direct reflected radiance at x2 only, excluding Le(x2), all reflected suffixes with another intermediate scattering vertex and cache values containing longer transport. Its outgoing direction is towards x1. For genuinely Lambertian x2 this Z1 distribution/expectation is independent of that outgoing direction within the permitted hemisphere.

For a simple all-light-support NEE-only initial implementation:

Z1(x2) = EvalBSDF2(omega_light) * Le_light * visibility * W_light / pOmega_light

Here EvalBSDF2 follows the renderer's f*cos convention (do not multiply the cosine twice); W_light is the finalized RIS light-selection contribution weight when RIS is used, and pOmega_light is the returned conditional solid-angle density. With direct light draws instead of RIS, the equivalent denominator includes light-selection probability and its conditional point/direction PDF. Match the exact pinned light sampler semantics rather than transplanting1/r.weightSum as an unconditional density. Area/continuous-environment and delta analytic lights require their respective mixed-measure conventions. Start with verified supported lights; reject unsupported emissive-light support rather than lose a domain silently.

NEE-only here uses light/BSDF path MIS weight1 because a BSDF light-hit counterpart is not included in Z1. Alternatively include both NEE and BSDF emitter/environment techniques at x2 with their exact complementary MIS, but terminate after the terminal light hit and do not include NEE at x3. Never downweight NEE against a BSDF counterpart that was removed by truncation.

Store x2 position, its correct geometric normal, Z1 and q1. The initial GI estimator before reuse is:

I_GI_draw = EvalBSDF1(omega12) * Z1(x2) / q1(omega12|x1)

The primary BSDF and1/q1 must each occur exactly once. This matches the conceptual decomposition of the existing GI export, but the current export's suffix RGB must be replaced/restricted; clearing it after several deep contributions is too late.

Prefer a dedicated short-GI producer first: it traces the primary proposal, evaluates Z1 at x2 and writes an explicitly tagged GI-short record. That avoids retrofitting restirGIStarted before x2's eligibility is known, and makes its acceptance/PDF visible. A later optimization may share the native first continuation through a carefully factored export. Correlation between GI-short/native-short/PT-long samples is allowed by linearity if each estimator is correct, but requires its own variance assessment; distinct effect seeds make the first ablation easier to inspect.

GI reuse and an existing approximation barrier

For fixed endpoint x2, shifting the primary from a to b maps source solid angle to destination solid angle with:

J_GI = G(b,x2) / G(a,x2)
G(a,x2) = abs(n_geom2 dot direction(x2→a)) / distance(a,x2)^2

This is the ratio dOmega_destination/dOmega_source; reverse mapping uses its inverse at the same endpoint. The target at receiver b is luminance(EvalBSDF_b(direction b→x2)*Z1). Its resampling weights and inverse normalization need the actual Jacobian, source UCW, confidence and correct visibility support.

Current RtxdiApplicationBridge.hlsli::RAB_ValidateGISampleWithJacobian rejects outside[0.1,10] and clamps accepted Jacobians to[1/3,3]. Current GI defaults also use Basic correction, boiling, permutation and GIFinalShading's roughness-dependent final/initial blend. These are not a strict unbiasedness proof. For a strict reference track: disable sample-dependent filters/approximate final blend, use the raw Jacobian and explicit finite/support checks, and evaluate the necessary visibility/normalization terms. If rejection limits remain, their partial-map support must be treated consistently in both directions; an incorrect Jacobian cannot be made correct by labelling it a quality control.

Even after these fixes, scalar secondary radiance is insufficient for general glossy/view-dependent x2. To extend GI beyond L, store the light/path sampling payload and material state required to reevaluate its target for the new outgoing direction, with full proposal/selection UCW and support; update every forward/inverse/final evaluation. That is an explicit root-overlay extension, not the existing32-byte GI reservoir magically becoming a general path reservoir.

Native short/fallback execution

Current PT's immediate primary return must be replaced in combined B8 mode. Native needs enough continuation to estimate its assigned k2 fallback:

  • At P=false, keep native transport through the user's original cap; prevent GI collection for that fallback primary.
  • At P=true, keep native k0/k1 only as assigned by D, and trace the short branch far enough to see x2 and, for L=false, the terminal BSDF emitter/environment after scattering at x2.
  • For L=false, native NEE at x2 and its BSDF terminal counterpart at x3 form k2 and keep complementary MIS.
  • After terminal emission at x3, stop before NEE at x3 or another continuation; those are k≥3 and belong to PT-long.
  • For L=true, native k2 is masked out because GI-short estimates it. Preserve any k1 Le(x2) handling before this decision.

Use an explicit radiance-routing predicate in hit/NEE/miss accumulation. Do not merely set a global bounce cap2 for all pixels: P=false native fallback still requires the original cap, and an emission hit's order differs from the NEE vertex's order. The existing clean-truncation comment in HandleHit explains why the terminal BSDF emission must be collected before stopping.

If a reservoir happens to select zero light, native must not reactivate the same domain as an opportunistic fallback. That selection is an ordinary zero-valued estimator outcome. Fallback is determined before sampling by supported geometry/material/frame contract, not by radiance or successful selection. Likewise, finite sanitization is diagnostic, not permission to substitute a second estimate of already-owned transport.

PT-long filtering and source PDF

The runtime uses light-inclusive path length d: k=d-1 for the current primary anchor. Sample::RtxdiSetupFrame already maps native capB to max path lengthB+1. PT-long accepts d≥4, while respecting d≤B+1.

At ctx.GetBounceDepth()==2, the first traced secondary is x2 and RecordNeeLightSample would create d3 (k2); reject that contribution for PT-long. Still advance the path/reconnection state: later NEE at x3 creates d4 (k3), which is valid. For BSDF emissive/environment recordings the stored length is the current bounce depth; reject d2/d3, accept d≥4. Rejecting early contributions must not prematurely terminate the prefix needed by long paths.

Implement one explicit contribution-acceptance function before each initial RIS stream operation, and preserve the same domain in stored paths and all target/replay/inverse evaluations. Do not change the proposal into a conditional distribution “given long path” without recording that conditioning probability. Empty path trees contribute zero; they are not discarded from the initial-sample count to inflate the estimate. Existing roulette survival PDFs and full BSDF/NEE proposal weights remain in their existing roles; filtering an integrand term does not remove its sampling factors.

Hybrid shifts preserve d and therefore the k≥3 class, which is one reason to prefer a pure-length PT domain. Reset/reject old reservoirs with d<4 and any prior domain-contract version. The existing packed path reservoir has no version field: use an application-owned history generation/receipt and explicit clear, or a root sidecar with validated identity. Do not silently reuse standalone full-indirect GI/PT history in B8-long.

Alpha, delta, media and material boundaries

  • Alpha-rejected triangles and false interfaces do not increase k. Keep native and bridge alpha tests, opacity interpretation and sample coordinates consistent; do not make “number of intersections” the domain index.
  • A delta first scatter uses discrete mass, not a solid-angle q1. First strict P excludes primary delta/mixed-delta responses, leaving full native fallback. A later lobe-labelled partition must record selection mass, transport component and reference conventions explicitly.
  • Delta events later in PT-long remain valid under its hybrid/replay/discrete-weight rules. At a non-L secondary, native k2 includes delta-secondary light hits as a fallback domain.
  • Native GI currently treats primary scatter PDF0 as empty, so it cannot be used as a delta measure carrier without an extension.
  • Transmission/media/shadow transmittance, nested state, binding diffuse limits, PSR, reconstruction and multiple layers remain independently gated. Restricting the contribution length does not solve their replay/medium/PDF problems. The current global opaque/nonbinding-cap PT checks remain until their separate acceptance work completes.
  • Geometry/material/light changes can change P/L or direct support. Reevaluate eligibility and invalidate affected histories; a cached GI radiance sample from a now-ineligible material cannot keep claiming the old domain.

Light-list, path-budget and DI reuse corrections

The matched-reference failure led to a local-light isolation experiment. A deterministic 8×8-per-triangle quadrature using the same reconstructed DI surface produced mean RGB [0.302392,0.301655,0.281082], close to native direct-reference [0.303280,0.302282,0.282504]. Thus the large excess was not explained by a different material model or duplicated native direct lighting. Component readback showed only primary emitter radiance before DI.

The concrete cause was in PrepareLightsPass: an allocated environment-map resource was treated as a registered scene light. With no scene environment record, subtracting one from zero infinite lights underflowed; the environment index wrapped into the local triangle list. The correction counts actual records and appends a real synthetic global-environment record when a baked map has no corresponding scene light. This preserves native baked sun/override illumination rather than inferring a light solely from resource allocation. Extra capacity and previous-frame mappings are tracked; skipped primitive records are pruned from temporal mapping.

A first registered-record repair reduced direct-only initial DI mean radiance to within approximately0.3–0.4% of the reference across uniform/power/ReGIR proposals, with and without BRDF candidates. These are diagnostic captures, not a convergence claim. The subsequent synthetic-record build and supported-light variants require their own verification.

Two additional contracts were repaired: geometry-hit light indices now include the current light-buffer region offset, while the power-PDF callback subtracts that offset before indexing its local texture and normalizes by actual texture area. Neither light loading nor temporal translation adds another offset. Native bounce limit B permits the terminal emitter after B scattering surfaces, whereas RTXDI PT counts the light vertex in its path length. Initial and replay PT limits therefore use B+1; this correction is measured separately from the light-list repair.

DI reuse has two additional validation controls. The inherited boiling filter intentionally removes high-weight samples. In pinned runtime f12037f, raytraced spatial resampling caches a neighbor before the naïve-sample discount rejects its contribution, but the later normalization pass still counts its mass. B2 now defaults the naïve-neighbor discount off to avoid that normalization defect. --strictDIValidation true also disables DI boiling and explicitly keeps the discount off while retaining raytraced bias correction; it does not modify the child runtime or promise unbiased GI. Shared notation and preprocessing: proposed project conventions

Let In,t,i,c be linear scene-referred RGB radiance from independent run n, frame t, pixel i, channel c; Rt,i,c is the high-quality reference for that exact frame, scene, geometry/LoD, shutter/lens/filter and lighting state. Let Y(I)=0.2126IR+0.7152IG+0.0722IB after conversion to linear Rec.709 primaries. These luminance coefficients and the conversion rule are our documented conventions, not a claim that all papers use these exact coefficients. Store source primaries, white point, radiometric scale, units/exposure multiplier and conversion matrix.

Use float HDR captures before tone mapping, sharpening, UI and display transfer for radiometric metrics. Do not compute these metrics on heatmaps or 8-bit screenshots. Do not normalize each candidate to its own brightness: that can conceal energy bias. If storage uses pre-exposure, undo the recorded multiplier before evaluation. Keep identical finite-value handling across variants; count NaN/Inf/negative samples and report them separately rather than silently hiding failures with clamping. Define the reference's uncertainty from independently converged reference batches; reference noise must be small enough to resolve the proposed difference.

Always state whether a reported scalar is a mean over channels, pixels, frames or independent runs. Evaluate each run before averaging its metric for single-frame quality. Evaluating only the image averaged across runs answers a bias/convergence question and suppresses single-frame noise.

Metric definitions and attribution

SMAPE following CGNS

For nonnegative luminance yi=Y(Ii), ri=Y(Ri), use

SMAPECGNS=100|Ω|∑i∈Ω|yi−ri||yi|+|ri|+10−4.

This follows CGNS footnote3 p8. Preserve its factor 100, rather than substituting the factor 200 used by another common SMAPE convention. The fixed epsilon is tied to image scale; record the radiance scale to make comparisons reproducible. SMAPE limits bright outlier dominance but is not a pure variance statistic: bias contributes, and saturated-color errors can be underrepresented in luminance. Report an RGB-sensitive metric alongside it. The papers do not establish external display exposure settings for this formula; compute on the explicitly recorded HDR scale as our test convention.

MAPE following SPMIS and PG, with explicit project channel handling

SPMIS §6 p7 writes

MAPE=mean(|I−R|R+0.01mean(R)).

PG footnote4 p8 instead explicitly uses grayscale reference R~ in the denominator:

MAPEPG=mean(|I−R|R~+0.01mean(R~)).

The excerpts do not completely specify color conversion and reduction. Our named MAPE_RGB_Ydenom resolves them: average absolute RGB error over all channels/pixels, divide each channel's error by Y(Ri)+0.01μR, where μR is the full reference frame mean luminance. Preserve the full-frame μR when reducing an ROI so its normalization does not change merely because the crop changes. This ROI choice is ours. Also emit MAPE_Y on luminance if a direct scalar-luminance comparison is useful. Keep values as ratios; multiply by 100 only for a separately labelled percent display. If μR=0, report the relative metric unavailable and report absolute error for that frame rather than silently inventing a denominator.

RelMSE: explicitly proposed project definition, not recovered LoD implementation

Let μR=meaniY(Ri), di=Y(Ri)2+(0.01μR)2. Define

RelMSEproject=13|Ω|∑i∈Ω∑c∈{R,G,B}(Ii,c−Ri,c)2di.

This is an original measurement convention inspired by relative-error reporting in the ReSTIR literature. It is not asserted to reproduce ReSTIR LoD's exact scores. Its denominator is not (Y(Ri)+0.01μR)2; those alternatives differ. Record the formula/version in every result. Use full-frame μR for ROI scores and flag all-black references as unavailable for this relative measure. Include absolute linear RGB MSE in parallel,

MSERGB=13|Ω|∑i,c(Ii,c−Ri,c)2,

because relative normalization emphasizes dark regions while MSE emphasizes bright energetic outliers. Do not switch definitions between canonical configurations or retained legacy datasets, or rank them against published RelMSE numbers from another convention.

HDR-FLIP and displayed-image FLIP

PT++ explicitly uses HDR-FLIP. It combines errors from exposure-compensated, tone-mapped image pairs. The official implementation exposes both images equally, computes LDR-FLIP at each exposure, and takes the per-pixel maximum; mean HDR-FLIP averages that map. Thus

EiHDR=maxe∈ELDRFLIPi(T(2eI),T(2eR);PPD),FHDR=meaniEiHDR.

This compact definition delegates LDR-FLIP's perceptual color/feature filtering to the official evaluator; it is not a substitute reimplementation. Pin evaluator revision/backend, PPD, tone mapper, exposure start/stop/count and input conversion. Auto exposures derive from the reference in the inspected implementation; save resolved values and reuse them across variants. PT++ Fig15 p17 notes FLIP is less sensitive to fireflies/correlation but remains sensitive to brightness differences. Sources: HDR-FLIP publication, official evaluator, parameter documentation.

Our proposed reporting is mean plus an uncolored error map and ROI/high-percentile summaries. Evaluate full-frame FLIP first, then reduce its map over ROI masks: cropping inputs before the evaluator changes spatial-filter boundaries and potentially auto-exposure. For the actual displayed output, separately evaluate LDR-FLIP after the fixed documented display transform. Do not call that HDR-FLIP or mix it with raw-radiance scores. A static perceptual image metric does not measure temporal flicker.

Relative spatial covariance and temporal autocovariance: exact CGNS equations

CGNS Appendix A p16 uses grayscale luminance yn,i, sample mean y¯i=N−1∑nyn,i, and ϵ=10−4:

rij=1N−1∑n=1N(yn,i−y¯iy¯i+ϵ)(yn,j−y¯jy¯j+ϵ).

It averages rij in radius-8 disks, then over pixels. Although introductory wording mentions ground-truth normalization, the printed equations normalize by the sample mean, not R. Do not silently replace the denominator when claiming reproduction. The text does not explicitly resolve inclusion of the center pixel or border weighting; our convention is to exclude the center (self-variance), average valid neighbors per center, then average centers. Label this convention; exact author-code verification may require changing it before claiming bit-level reproduction.

For N independent video sequences of the same static scene, define separate means at each frame and use lag T=3:

ai(t)=1N−1∑n=1N(yn,t,i−y¯t,iy¯t,i+ϵ)(yn,t+T,i−y¯t+T,iy¯t+T,i+ϵ).

Average over valid frames/pixels. CGNS reports similar behavior for lags 1–5. This is normalized covariance, not Pearson correlation: do not divide again by standard deviations. Show covariance and error together: increasing independent noise or resetting history can reduce covariance while harming quality. Full-frame static-scene covariance is the paper-aligned measurement; moving cameras/objects require separate treatment below.

ROI, flicker and recovery: proposed definitions

Derive masks from deterministic high-quality geometry/visibility metadata, not each algorithm's observed error. Record total/full-frame area and invalid counts for every ROI. Report whole frame plus (a) first visible/disoccluded pixels, (b) time-since-visibility age buckets, (c) thin geometry/foliage, (d) glossy/specular paths, (e) shadows and caustics, and (f) stable regions. A hard-pixel ROI based on geometric neighbor compatibility can follow CGNS §7 p9, but freeze its definition across variants. Multi-layer §6 p5 motivates disocclusion-specific scores because whole-frame averaging dilutes them.

For flicker under motion, compute errors relative to the per-frame reference and warp only geometrically valid correspondences. A proposed supplementary statistic is

Flickerproject=mean(t,i)∈V|et,i−Wt−1→t(et−1)i|,et,i=Y(It,i)−Y(Rt,i)Y(Rt,i)+0.01μRt.

V excludes disocclusions, invalid warps, topology changes and unsupported transparency; document interpolation and mask rules. This is our metric, not CGNS Eq17. Report unmatched/disoccluded regions in their own recovery curves rather than filling missing warped errors with zero. Static sequences additionally use exact CGNS covariance. A camera-locked flicker score can otherwise mistake real motion for stochastic instability.

For an event at t0, plot ROI error Q(k) versus frames k=t−t0 and elapsed GPU milliseconds; include confidence bands. Also report a fixed-window mean error/AUC K−1∑k=0K−1Q(k), first-frame error, worst-frame error, and persistent residual. A proposed recovery time is the first k for which Q(k),…,Q(k+L−1)≤q*. Choose q*, hold length L, and window K from scene/use-case needs before evaluating candidates; publish them, do not present them as universal paper thresholds. If never reached, mark recovery as not reached by the capture horizon. Keep a decaying ROI cohort tied to the same surfaces/event, or explicitly state that the ROI evolves; otherwise changing mask membership can manufacture apparent recovery.

Bias, outliers and estimator checks

Use independent run averages at the same frame/event state to estimate b^i,c=N−1∑nIn,i,c−Ri,c. Show signed bias/energy maps as well as an absolute relative summary; attach uncertainty from both test and reference. PT++ Fig5 p9 reports mean(|bias|/ref); our stabilized luminance summary can use meani|Y(b^i)|/(Y(Ri)+0.01μR), explicitly labelled as our stabilized version. A confidence interval containing zero is not a proof of unbiasedness. Test strict estimator settings and interactive bias controls separately, including duplication history reduction, clamping and caches.

Retain raw max/high-percentile errors, firefly counts with a declared scale-aware definition, missing/invalid samples, and spatial error maps. Perceptual and relative metrics can suppress bright outliers; absolute MSE alone can overemphasize them. Use complementary measures and inspect failure sequences. Do not claim numerical stability from an appealing tone-mapped still image.

Primary source: Lin, Kettunen, Wyman, I3D 2026, DOI 10.1145/3804494. Public PDF carries CC BY 4.0. NVIDIA publication page links paper, supplement and video; it does not link official source code as checked. Third-party implementations are separate evidence, not the authors' code.

Source findings. Reciprocal neighbor pairing amortizes forward/backward spatial shifts (§3, pp4–6). Dual footprint tests with a roughness safeguard improve hybrid-shift reconnection (§4, pp6–8). This sample-dependent confidence adjustment is deliberately biased: Figure 5 reports 3.25% mean absolute relative bias in Kitchen. Disabling it restores unbiasedness (§7.4, p14). Other changes include unified DI/GI reservoirs, compressed storage, replay compaction, forced NEE reconnection, roulette restricted to initial generation, vector-weight shading and dual motion vectors (§6, pp10–11). Add an explicit interactive mode for biased controls and report their energy error separately. Reserve replay output buffers for immutable pass inputs so reciprocal writes cannot race or read partially updated reservoirs.

Weighted sampling picks M neighbors from K cheap candidates; M=1 uses A-Chao, M>1 uses A-ES (§5, p8). Suggested K is 8–32 and radius 30–100 pixels (§6). Fixed-radius reuse can increase spatial covariance; larger radius changes the quality/correlation tradeoff. Main tests use M=1, K=32, 1080p, RTX 5880 Ada, four static-camera scenes with supplementary animations (§7, pp9–13). Fast mode reduces SMAPE by 5.8–29% and temporal covariance by 22–49% with 1.3–4.4% full-frame overhead. The heuristic ignores visibility, does not solve disocclusions, and may poorly represent lens/time/volume path domains (§8, p14).

Proposed RTXPT integration. For future B1/B2, reuse the existing RTXDI 3.1 reference selector, Libraries/Rtxdi/Include/Rtxdi/PT/SpatialNeighborSelection.hlsli::RTXDI_PTSpatialNeighborSelection, and its Full Sample bridge as the integration model. Wiring that selector and its required G-buffer contract into the RTXPT 1.9 renderer is proposed implementation, outside this baseline-and-roadmap stage; independently translating the Falcor pass is unnecessary. Do not modify B0 to enable reference SDK features. Produce neighbor indices from stable primary-hit positions and normals; dispatch it before spatial reuse. Keep a separate neighbor buffer per sampling layer if subsequent multi-layer temporal reuse changes surface ownership. Expose candidate count, returned-neighbor count and radius independently. Do not add luminance, reservoir confidence, sample ID, or target weight to this heuristic while claiming its original unbiasedness proof: those inputs depend on the samples being integrated. Material ID can be a sample-independent optional test, but the paper reports no measurable gain in its tested scenes.

Acceptance proposal. Compare matched-radius results first, then equal-covariance operating points across radii; include worst 10% geometrically difficult pixels and whole-frame metrics. Verify boundaries, background, thin geometry, material discontinuities and changing resolution. For defocus and motion blur, explicitly test whether one primary-hit G-buffer is adequate. Stochastic Pairwise MIS for Unbiased Large-Kernel Reuse in Real-Time

Primary source: Hedstrom et al., Eurographics 2026, DOI 10.1111/cgf.70391. PDF states Creative Commons Attribution. NVIDIA publication page links official minimal source archive. Checked archive SHA256: 02be1910858db4cd340f642edbf5a0405395f8056a21238ee832ce5c08f670b7. Its nine files include README, C++ and Slang but no license file or copyright/permission notice. Paper access terms do not establish code reuse rights; do not copy archive code into the fork until terms are resolved.

Source findings. Stochastic MIS estimates reuse over M inputs by shifting only N selected inputs and separately estimating the canonical weight (§§3–4, pp4–5). Multiplicity and inverse selection probability compensate sample-dependent input choice; selection requires positive support wherever the relevant weight contributes (Eq15). Noncanonical selection uses confidence times source contribution (Eq17), while canonical estimation samples all input domains (§4.2). Scaling noncanonical confidence by N/M controls pepper noise (§4.3). GPU reuse cells group 8×8 tile pixels by object and quantized normal; separate lists retain all domains versus contributing reservoirs (§5, pp6–7). Tests use RTX4090 at 1080p, one initial path, eight bounces, N=3, canonical count=1 and M≤64 (§6). Source-domain importance can mispredict shifted contribution, and impoverishment remains (§7, p10).

Proposed RTXPT integration. Implement as a distinct spatial-reuse estimator behind a flag, with the same PT shift/Jacobian interface as the baseline. Define an immutable cell-builder output contract including all-domain confidence sums, contributing-sample lists, counts, selection contribution weights and overflow flags. Do not drop zero-contribution domains from canonical accounting. Preserve repeated-sample multiplicity; deduplication without multiplicity changes weights. A CGNS-prefiltered domain population is a later experiment: formally specify its conditioning and support, then derive the two-stage selection probabilities before coding. Independent combination is not established by either implementation.

Acceptance proposal. Start with finite synthetic discrete domains where exact sums and selection probabilities are enumerable, including zeros, duplicate draws and visibility failures. Compare stochastic means to full pairwise evaluation before testing large scenes. Exercise empty/overflowing cells, hash collisions, confidence quantization and asynchronous buffer barriers. Measure all cell-building and sorting costs; this is not simply a free replacement for three uniform neighbors. Use disocclusion masks and equal-GPU-budget comparisons, with a strict mode as the control.

ReSTIR PG: Path Guiding with Spatiotemporally Resampled Paths

Primary source: Zeng et al., SIGGRAPH Asia 2025, DOI 10.1145/3757377.3763813. Author page links paper and DOI, but no official code link as checked. The author PDF is explicitly for personal use and not redistribution. Link the PDF; export only original summaries and analysis. Public third-party renderer implementations exist but are not the authors' artifact or independent validation of this fork.

Source findings. Resampled path directions populate spatial/BSDF hash cells; four-component vMF mixtures fit local guiding distributions and guide next-frame initial paths (§4, pp6–8). The model approximates incident-radiance×BSDF×cosine; the directional marginal is exact in the diffuse simplification and can be suboptimal for glossy materials. Sampling mixes guiding and BSDF equally using one-sample MIS (§4.5). The prototype handles indirect guiding with separate ReSTIR DI, disables roulette and uses scene-dependent 3–9 bounce limits (§5, p8). Tests use 1080p on RTX6000 Ada. Reported memory is approximately 102.8 MB per bounce for path records plus 152 bytes per valid guiding cell (5–76 MB in examples). Guiding has substantial collection, fitting and sampling overhead; no general multiplicative speedup is established. Marginal approximation and reuse failure limit guiding (§6).

Proposed RTXPT integration. Add a path-record extraction contract after final reuse: replay selected paths or retain bounded bounce records, then splat only verified vertices. Compare replay cost against record bandwidth before choosing storage. Double-buffer distributions and version them by frame, camera/scene changes, material and sampler state. Extend initial generation, path PDFs and random replay coherently: a reused seed with a changed guiding distribution cannot silently imply the old path. Keep BSDF fallback for empty/stale cells and delta paths, account for the complete mixture PDF, and include that PDF in NEE MIS and hybrid-shift Jacobians. Treat the paper's no-roulette setup as a compatibility gap with PT++ roulette, not an automatic combination.

Acceptance proposal. Begin with diffuse guiding and an explicit bounded VRAM budget, then add glossy materials only after replay consistency and density tests pass. Test camera cuts, moving lights, disocclusions and hash eviction. Quantify startup and adaptation lag, un-guided initial candidate quality and total time-to-quality. Use diffuse interior/window transport and scarce caustic paths, but retain glossy and rapid-motion counterexamples where the marginal can fail.
