## Staging and correctness

Start with small independent estimator oracles and one reciprocal pair. An exact single-pair implementation is a useful first gate, but it does not by itself reproduce the paper's reported multi-neighbor schedule. Expand only with an explicit normalization derivation. Keep scalar reservoir selection, RGB shading marginalization and retained history state distinct.

Compaction changes scheduling, not the estimator domain: candidates that shift to zero can still contribute confidence/normalization and must not disappear from bookkeeping. Forward reuse and selected-sample inverse correction have a dependency; queues must preserve the required intermediate state. SER alone is not replay compaction.

Unified lighting needs a new direct/indirect ownership contract. It does not mean adding the outputs of separate ReSTIR DI, GI and PT solvers. Audit area/solid-angle light densities and terminal reconnection before injecting primary candidates. Keep the existing separate DI + PT configuration as an ablation.

Keep duplication reduction and other sample-dependent bias controls outside the strict radiometric reference preset. Implement each mechanism behind an explicit control and actual-setting receipt, then evaluate the combined configuration. Do not multiply the paper's individual speedups or assume its 2022 baseline matches RTXPT 1.9.
