# First B0/B1 capture analysis

`analyze_captures.py` reads the existing RTXPT1.9 CSV schema and PNG screenshots. It does not launch the renderer or fabricate missing whole-frame/GPU results. Python3.10+ is required. GPU CSV analysis uses the standard library; PNG analysis/tests need NumPy and Pillow (available in the host's bundled Python). The optional `--flip` adapter calls an already-installed official `flip-evaluator` package. It never installs one silently.

## Scope that must be preserved

The upstream `Rtxpt/SampleCommon/PathTracePerfLog.h` writes `buildMs`, `compactionMs`, and `fillMs`. `AdvancedSample.cpp:221,285â€“286` wraps the path-trace prepass and fill; the subsequent RTXDI calls are at316/319. **The CSV excludes RTXDI DI/GI passes.** It is insufficient to measure the performance of the migrated DI/GI shaders or claim complete-renderer speedup. The tool labels all timing summaries as partial logged-stage attribution. Full GPU critical-path timing requires additional verified instrumentation/profiling.

Each input CSV must be a separate process run, not an appended set of invocations. Pass an explicit half-open scene-time interval and verify it advances monotonically. Avoid screenshot-write timing: **only for a source-verified animation-enabled scene**, a sequence with record start10seconds, simulated60FPS and one captured frame can provide600warmup frames with no image writes; an interval such as `[4,10)` selects the final360pre-capture frames. Check the actual log and manifest rather than assuming all frames exist. Scene time is simulated time, not achieved throughput. Capture startup/loading/caches and history behavior require separate interpretation.

### Static-scene sequence pitfall found during the pilot

`Sample.cpp:1050â€“1074` advances scene time only when `EnableAnimations && RealtimeMode`; otherwise a disabled-update branch resets it to0. The initial convergence and kitchen scenes have animations disabled. Consequently, `captureSequence` can keep rendering indefinitely without reaching a positive `sequenceRecordStart`, even without `--stopAnimations`. Do not use the animated sequence template below as a static-scene completion harness. Protocolv2 deliberately uses this static property as a bounded unfocused-render guard. The partial-CSV analyzer rejects constant/resetting selected scene times for an advancing-sequence analysis, including a static `[0,1)` selection that would otherwise contain many frames while representing no progressing capture interval.

For accepted first static-scene timing, `run_timed.py` uses an active `captureSequence` guard: original static sceneTime stays0 and never reaches recordStart20, while `ShouldRenderUnfocused` remains true. The wrapper warms for45wall seconds, collects a15wall-second PID-filtered PresentMon trace, then deliberately terminates only its owned renderer. Validate zero PNG writes, sufficient rendered frames, actual render size and static sceneTime0. Do not add `--stopAnimations`, and reject original scenes with animation enabled. The initial non-capture attempt was invalid because unfocused rendering could stop; those runs are excluded. Keep image quality separate: use `captureSimple` at its source default64warmup frames, with a separately generated reference (initial convergence reference2048spp at exposure0; kitchen exposure2, matching `RegressionTesting-RUN.bat`). Wall-clock warmup and trace time are not simulated scene time and must be recorded independently. The runner owns actual launch/timing boundaries and external tool version; analyzers only process retained data.

Use five or more process runs for the planned confirmation protocol. Two are shown only for command brevity. The summary is a median of process-run medians, not a pooled frame median. It reports frame-distribution p95 within each run and the median of those p95s separately. A deterministic percentile bootstrap over run medians is supplied for three or more runs; its small-sample limits and independence assumptions remain material. Matching CSV columns cannot verify equal scene/camera/features/hardware; retain complete run manifests.

PNG metrics are decoded-RGB equality, changed-pixel fraction, encoded-sRGB RGB MSE/PSNR, and display-luma SMAPE100. Alpha is excluded. Equal pixels have mathematically infinite PSNR, encoded as `null` plus `psnr_identical_infinite=true` to keep valid JSON. Display-luma uses Rec.709 coefficients on encoded RGB; this is explicitly **not** HDR luminance or paper-exact radiometric SMAPE. A B0 regression image is a cross-version oracle, not converged truth. The optional official evaluator runs **LDR-FLIP**, records its package/native binary identity and PPD, and computes the full map before reducing any ROI. Official1.7 returns inactive HDR exposure defaults as `+inf` during LDR evaluation: the wrapper separates these under `inactive_hdr_parameters`, marks them not applicable and preserves the sentinels as strings. Active non-finite parameters, error maps or mean errors still fail. There is no substitute HDR-FLIP, MAPE, RelMSE, flicker, covariance or bias implementation here.

ROI masks are same-size image masks: nonzero grayscale pixels select the region. No resizing/cropping or denominator renormalization is hidden. Wrong dimensions, malformed/non-finite/negative timing data, empty windows, changed sampling settings and appended process logs fail explicitly. Synthetic tests verify formula and parser behavior only; their values must never enter renderer result tables.

## PresentMon process-frame analysis

`presentmon_analysis.py` handles the separately captured PresentMon2.x process stream. The accepted static-scene runner uses the protocolv2 active-capture/no-image-write guard,45wall-second warmup then a15wall-second trace; analyze a preregistered last600eligible rows and drop the final16rows. Require enough frames rather than silently shortening the window. This selection also works for a verified animation-enabled sequence after separately checking its no-image-write interval; selection indices alone do not prove that condition.

```powershell
python -B Benchmarks/tools/presentmon_analysis.py summarize Benchmarks/runs/B0-r1-presentmon.csv Benchmarks/runs/B0-r2-presentmon.csv --label B0 --process-name Rtxpt.exe --last-n 600 --drop-tail 16 --output Benchmarks/results/B0-presentmon.json
python -B Benchmarks/tools/presentmon_analysis.py summarize Benchmarks/runs/B1-r1-presentmon.csv Benchmarks/runs/B1-r2-presentmon.csv --label B1 --process-name Rtxpt.exe --last-n 600 --drop-tail 16 --output Benchmarks/results/B1-presentmon.json
python -B Benchmarks/tools/presentmon_analysis.py compare Benchmarks/results/B0-presentmon.json Benchmarks/results/B1-presentmon.json --output Benchmarks/results/B1-vs-B0-presentmon.json
```

One processID and swapchain must remain after the process-name filter; otherwise specify `--process-id` and/or `--swapchain`. Generated frames are excluded when FrameType exists: default accepted types are Original/NotSet, with counts preserved. If another label is source-verified as application-rendered, declare it with `--allow-frame-type`; do not guess enum meanings. Missing FrameType leaves exclusion unverified. Missing/NA GPU or display values remain unavailable. The parser rejects an insufficient selection, non-finite/negative timings, incompatible selection policies, and differing observed API/sync/tearing/present-mode sets. Store the exact external tool checksum/version in each run manifest.

CPUFrameTime/FrameTime describes CPU frame cadence. GPUBusy measures target-process active-engine time; GPUTime includes its GPU wait interval. DisplayedTime describes display residence. These are distinct scopes; inverse GPUTime/GPUBusy is not total renderer FPS. Per-frame distributions and run-level summaries remain separate. Tail truncation is an explicit capture assumption, not proof that loading/readback or trace loss is absent. Verify selected row indices/times and manifests before using a result. Source: [official console schema](https://github.com/GameTechDev/PresentMon/blob/v2.3.0/README-ConsoleApplication.md#csv-columns); PresentMon2.6 `--v2_metrics` selects that metric family.

## Future uncapped runs and driver recovery

The frozen B0/B1 results remain historical and were not comprehensively audited for external/driver caps. New renderer builds expose `--benchmarkUncapped`; root-owned runtime integration must log its effective VSync, application FPS limiter, Reflex cap/mode, frame-generation and unfocused-rendering state. Do not pass this new option to old B0/B1 binaries or label the flag alone as runtime verification. Capture sequence FPS controls scene-time stepping, not achieved renderer FPS.

`native/nvapi_caps.cpp` is a typed helper built against the repository's official pinned NVAPI headers/library. From a Visual Studio x64 developer prompt, compile it with the NVAPI include directory and `External/NVAPI/amd64/nvapi64.lib`; keep the executable and object under private work, not the public repository. Its default invocation accepts one absolute renderer path and performs read-only DRS queries. `cap_preflight.py --exe ... --helper ... --output ...` interprets foreground/background cap and VSync settings. `SETTING_NOT_FOUND` remains unknown; it is never converted to disabled.

`driver_cap_scope.py run --exe ABSOLUTE_EXE --helper PRIVATE_HELPER --state PRIVATE_NEW_STATE --receipt PUBLIC_SAFE_RECEIPT --command BOUNDED_BENCHMARK_COMMAND...` can temporarily create a UUID-named profile for the exact executable path when it has **no existing application association**. Existing profiles are refused, including shared profiles. It never rewrites their settings or changes globals. The three owned settings are foreground cap0, background cap0 and forced-off VSync. The helper verifies the scope before restoration and refuses to destroy external edits. The private state is written before apply and retained after failures; it contains original association/driver information and must never be exported. The public receipt omits profile names, paths and original settings. Use `driver_cap_scope.py restore` with the same exe/helper/state after a crash. A pending state must be explicitly restored before a new run.

Synthetic tests cover original absence, existing-profile refusal, ambiguous apply failure, restore failure/recovery, external modification refusal and wrong-executable recovery. These tests are not a real-driver mutation/readback/restore test. The first real scope test must be separately coordinated before benchmark execution. Third-party frame limiters remain outside NVAPI coverage, so no helper result alone proves a completely uncapped system.

The first real scope smoke on2026-10-28 applied and read back the three owned settings, then exposed a restoration guard failure: DRS normalized path separators and the original raw full-path string comparison rejected the same Windows path. The guard now normalizes slash spelling and case while retaining full-path equality, exact owned-profile association, one-app/three-setting cardinality and unchanged-value checks. A fresh read-only inspection confirmed the same77-character full path and owned profile; restoration then succeeded and the original absent association was independently read back. First-failure evidence remains private. The native `--self-test-paths` mode exercises equivalent Windows spellings and rejects different folders or basename-only identity without initializing the driver.


For the new experimental PT path, `run_capture.py --mode dipt` and `run_timed.py --mode dipt` request DI on, GI off and ReSTIR PT on. They do not assert support or convergence; the renderer's own feature/scene gates and validation remain authoritative. `run_timed.py --benchmark-uncapped --driver-cap-audit ACTIVE_AUDIT_JSON` additionally requires a matching fresh (<60s) executable audit with explicit driver caps0/0 and forced-off VSync, passes `--benchmarkUncapped=true`, and rejects missing effective renderer settings or nonzero PresentMon SyncInterval. Driver/external coverage is separately recorded; the manifest does not claim every third-party limiter is known. The native profile scope's restoration receipt must accompany the run evidence.

## RTSS overlay cap coverage

`rtss_caps.py` uses a private **x86** build of `native/rtss_caps.cpp` and the installed SDK's `RTSSHooks.dll` API. The SDK sample explicitly requests administrator execution. Read-only audit is allowed without elevation but mutation fails closed unless the token is elevated; a VirtualStore-only zero limit is not accepted as live-hook cap verification. `--install-dir`, `--exe`, `--helper`, `--state` and `--output` identify the exact installation, renderer basename, private helper/recovery state and safe receipt. The mutation path refuses existing application profiles. The SDK profile scope is the executable **basename**, not a full-path selector, so the helper also refuses apply/delete while any renderer with that basename is running. It creates only a temporary application profile with documented FramerateLimit0, verifies SDK/file identity and disabled frame/frametime/scanline limits, and removes only the unchanged created profile. Global settings are never saved. The first non-elevated scope exposed VirtualStore redirection; recovery verified original application absence and unchanged global232. An administrator scope test would be required for future automatic mutation; the current user-preserved read-only path below does not require it. Keep ownership/recovery files and original profile information private.

The current user-confirmed path instead preserves the user's existing **RTXPT profile0 overriding global232**. Use `rtss_caps.py --action audit ... --user-confirmed-disabled` for a read-only snapshot. On the timed wrapper, pass `--rtss-install-dir INSTALLATION --rtss-helper PRIVATE_X86_HELPER --rtss-user-confirmed-disabled`; it performs read-only fresh (<60s) audits before launch, before PresentMon measurement and after measurement. The validator requires matching executable/helper/SDK hashes, effective SDK cap0, zero physical selected-profile frame/frametime/scanline settings, and no ambiguous/VirtualStore application profile. A selected installed application profile may correctly override a nonzero global limit; absence instead requires a zero global fallback. The public manifest records selected-profile hashes and user-confirmed/SDK/physical-profile authority, with `mutation_performed=false` and no restoration. Other potential external limiters remain outside this specific coverage. **Never run the RTSS temporary scope or restore an old global232 state over the user's current profile.** The administrator requirement applies to SDK mutation, not this preserved-profile read-only path.


### Linear HDR diagnostics (B2 development builds)

`run_capture.py --linear-hdr` requests the renderer's `--captureLinearHDR true` option and requires one PFM plus metadata sidecar for each PNG. Original B0/B1 and benchmark-controls-v1 builds do not implement this switch. Realtime AA0 capture reads stored OutputColor; reference mode reads AccumulatedRadiance. PFM RGB values are neither tone mapped nor exposure corrected. Source precision, row pitch and nonfinite counts are recorded. HDR readback waits for GPU idle and is excluded from throughput timing.

`analyze_hdr.py --reference REFERENCE.pfm --test TEST.pfm --output METRICS.json` measures the explicitly documented linear RGB MSE, CGNS-style luminance SMAPE, MAPE RGB with luminance denominator, and project RelMSE. It uses Rec.709 luminance coefficients and full-frame reference normalization. The parser checks payload size, endian, orientation and scale. Nonfinite/negative radiance is rejected; relative scores are unavailable for an all-black reference. HDR-FLIP is not implemented by this tool. One image comparison does not establish independent-seed statistics, estimator bias or reference convergence.

The cap verifier accepts the exact effective-settings log format from both B2 and the separately identified benchmark-controls-v1 adapter. Unknown/request-only log messages remain invalid.


PT HDR capture also writes a packed-reservoir `.pt.bin` and ABI/slot metadata. `inspect_pt_reservoirs.py --binary CAPTURE.pfm.pt.bin --output STATS.json` decodes only the pinned RTXDI 3.1 f12037f 64-byte ABI, applies tiled addressing and reports M/age/finite-state statistics. This is a post-frame snapshot: semantic indices can alias the same slot; it is not an intermediate-pass trace. The raw binary can be large. It does not establish correct PDFs, Jacobians or estimator bias.

For active PT, capture warm-up now resets caches once and preserves history on subsequent warm-up frames. Repeated accumulation-only reset flags previously cleared PT history through the captured simple-screenshot frame. Reference and original DI/GI capture behavior is preserved. Tests should record actual reservoir history participation rather than inferring it from an enabled checkbox.
